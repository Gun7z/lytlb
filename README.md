# 洛亚提自由联邦 · 市政厅官网｜GitHub Pages 发布包

这个文件夹里的内容，原样上传到 GitHub 仓库的**根目录**，就能得到一个不会 404 的官网。

| 文件 | 作用 | 必须放根目录 |
| --- | --- | --- |
| `index.html` | 网站本体（单文件，CSS/JS 全内联） | 是 |
| `content.json` | 站点数据：白名单、头衔、发布、页面正文、云端配置 | 是 |
| `supabase.js` | Supabase 客户端（离线可用，加载失败才去 CDN） | 建议 |
| `404.html` | 访问错地址时的兜底页，3 秒自动回首页 | 是 |
| `.nojekyll` | 空白文件，关掉 Jekyll 处理，防止某些文件被吞 | 是 |
| `supabase.sql` | 建表脚本，只粘进 Supabase，不用传仓库 | 否 |

---

## 一、发布步骤（网页版，3 分钟）

1. 新建仓库：名字用英文（如 `lytzy`），可见性选 **Public**（私有仓库免费账号开不了 Pages，会一直 404）。
2. 进入仓库 → **Add file** → **Upload files** → 把这 3 个文件拖进去（不要建子文件夹）→ Commit。
3. 仓库 **Settings** → 左侧 **Pages**：
   - Source 选 `Deploy from a branch`
   - Branch 选 `main`，文件夹选 `/ (root)`
   - 点 **Save**
4. 等 1～3 分钟，到仓库 **Actions** 页看到 `pages build and deployment` 变成绿色对勾。
5. 访问：`https://<你的用户名>.github.io/lytzy/` —— **结尾的斜杠要带上**。

想做成 `https://<你的用户名>.github.io`（不带仓库名），把仓库名改成 `<你的用户名>.github.io` 即可，文件照样放根目录。

## 二、404 的原因对照表

| 现象 | 真实原因 | 怎么修 |
| --- | --- | --- |
| 仓库地址打开就是 404，Actions 也没报错 | 根目录没有 `index.html`，或名字写成 `Index.html` / `index.htm` / 带中文或空格 | 必须是全小写 `index.html`，且在根目录 |
| Settings 里 Pages 一片空白 | 没开启 Pages | 按上面第 3 步设成 main + `/ (root)` |
| 刚点 Save 就访问 → 404 | 首次构建需要 1～3 分钟，这期间是 404 | 等 Actions 出现绿色对勾再刷新 |
| 首页能开，点导航却 404 | 用了路径式链接（如 `/officials`），GitHub 上根本没有这个文件 | 本站是 `#` 路由，链接形如 `/lytzy/#officials`，见下方说明 |
| 自己电脑双击能开，GitHub 上打不开 | 文件名大小写不符（GitHub 区分大小写，本地 Windows 不区分） | 统一小写文件名 |
| 页面打开但没样式 | 把 CSS/JS 拆成了外部文件，又用了绝对路径 `/style.css` | 保持单文件内联；本项目已全部内联，无需额外文件 |
| 私有仓库一直 404 | 免费账号不支持私有仓库 Pages | 仓库改 Public |
| 改了内容还是旧的 / 一直 404 | 浏览器缓存了旧响应 | Ctrl+F5，或换隐身窗口 |
| 访问 `.../lytzy`（不带斜杠）变成 404 | 少了结尾斜杠时跳转偶发失败 | 地址补上结尾 `/` |
| 上传 `.nojekyll` 提示"空文件不能提交" | 网页端限制 | 在文件里敲一个空格再提交，效果一样 |

## 三、链接形式说明

本站是单页应用，所有视图靠地址栏 `#` 后面的名字切换，所以：

| 想打开 | 正确链接 |
| --- | --- |
| 首页 | `https://<用户名>.github.io/<仓库名>/` |
| 官员架构 | `https://<用户名>.github.io/<仓库名>/#officials` |
| 宗教文化 | `https://<用户名>.github.io/<仓库名>/#religion` |

带 `#` 的链接可以直接发给别人、收藏、刷新，都会落在对应页面。如果手抖打错（如 `#official`），会自动回落到首页，不会白屏；如果打错的是 `#` 前面的路径，则由 `404.html` 接住，3 秒后自动回首页。

### 方式三：让我改（不用碰代码）

直接说“哪个页面、哪句话改成什么”，我改文件、验证完，你再上传。

### 「用户」页说明（重要）

在线 / 离线只反映**这台电脑的这个浏览器**：当前登录的账号记为「在线」，同一浏览器里注册过的其它账号记为「离线」。

账号数据存在浏览器的 localStorage（`lyt_accounts` 存账号，`lyt_meta` 存注册时间和最近活跃），不上传服务器——所以别人在自己设备上注册的账号，你在这里看不到。要做到跨设备、真实的实时在线人数，必须接入后端（Supabase / Firebase / 自建接口都行），纯静态页面做不到。

另外密码是明文存在本机浏览器里的，这个登录只适合站内自娱，别拿真实账号密码来注册。

### 四个常用改法

**1. 改一段文字** —— 搜到那段中文，只替换 `<p>` 与 `</p>` 之间的字，别动尖括号和引号。

**2. 加一位官员** —— 找到对应部门的 `<div class="tree-children tree-line">`，复制一整个 `staff-card` 块，只改这三处（职能那行可留可删）：

```html
<div class="staff-card">
  <div class="staff-avatar-square">镇</div>
  <div class="staff-info">
    <p><strong>职位：新镇长</strong></p>
    <p>账号 ID：<span class="staff-id">新账号名</span></p>
  </div>
</div>
```

**3. 加一个新页面** —— 必须改两处，两处的名字一模一样，否则点了没反应：

```html
<!-- ① 导航区里加一行 -->
<a href="#news" data-page="news" class="nav-link">新页</a>

<!-- ② 主内容区里加一块 -->
<div class="page-block" data-id="news">
  <div class="section">
    <h2>新页标题</h2>
    <p>正文内容。</p>
  </div>
</div>
```

**4. 换主色** —— 只改文件顶部 `:root` 里的 `--primary`（现值 `#5B8DEF`），按钮、标题竖线、高亮会全站一起变。

### 四条硬规矩

1. `index.html` 不能改名，必须留在仓库根目录——改了必 404。
2. `content.json` 不能删、不能改名，必须和 `index.html` 待在同一个目录——删了白名单和自定义内容会退回出厂版本。
3. 折叠树的 `tree-head` 后面必须紧接 `tree-children`，中间插别的东西会导致点了展不开。
4. 登录注册的账号存在浏览器本地，不在文件里；换浏览器、换设备就要重新注册，这是设计如此。

## 五、服主账号与白名单

### 账号权限

| 账号 | 密码 | 权限 |
| --- | --- | --- |
| `Gun7z` | `Gun7z` | 服主：导航多出「管理」入口，可改白名单、删本机账号、编辑页面内容 |

其它人注册后是普通成员，看不到「管理」。服主不用先在本机注册，直接在右上角输 `Gun7z` / `Gun7z` 就能进。

### 注册必须先加白名单

白名单存在 `content.json` 的 `whitelist` 里，默认只有 `["Gun7z"]`。不在名单里的名字，注册会被拒并提示「不在账号白名单内，请联系服主 Gun7z 添加后再注册」。

流程：服主登录 → 管理 → 账号白名单 → 加名字（一行一个）→ 保存 → 导出 `content.json` → 上传覆盖到仓库 → 等 1 分钟 → 对方才能注册。

### 改内容并上传

1. 服主登录 → 导航「管理」→ 内容编辑
2. 选页面 → 改标题、改正文（一行一段，空行忽略）→ 点「应用到本站」，本机立刻看到效果
3. 点「导出 content.json」，得到文件
4. 上传覆盖到仓库根目录 → 等 1 分钟 → 所有人看到新内容
5. 确认线上正常后点「清除本机草稿」，否则你的浏览器会一直用本机草稿盖住线上版本

官员架构、用户页不在内容编辑范围内（那两块是结构化数据）；要加官员仍按第四节改 `index.html`。

### 头衔授权（决定谁能发布）

管理台 → 头衔授权：填账号名（输入框可直接选白名单里的人）+ 选头衔 → 点「授予」。

头衔选项直接取自「官员」页的 20 个职位（联邦元首、联邦首相、各部门总长/部长/议长、各镇领主、长公主、公主…），官员页改了职位，选项跟着变。

- 被授予的人登录后，导航多出「发布」，才能发文；点「撤销」立刻失去入口。
- 没有头衔的成员看不到「发布」，手动输 `#post` 也会被弹回首页。
- 头衔记在 `content.json` 的 `titles` 里，导出上传后对所有设备生效。

### 发布内容

导航「发布」→ 先选**发布位置**（除「官员」页外的导航页面都能选）→ 填正文（换行会保留）→ 可选上传配图（自动压到长边 1080 的 JPEG）或直接贴图片链接 → 发布时间自动记录 → 点「发布」。

发出去的内容会挂在你选的那一页**下方**，标题是「本页发布 · N 条」，按时间倒序；没有内容时这一块自动隐藏，页面看起来和原来一样。

此时只有你自己浏览器里能看到。

### 评论

每条发布下方都有评论框，**任何已登录的账号都能评论**（不需要头衔），未登录只显示「登录后可以评论」。

- 评论存在浏览器的 `lyt_comments` 里，按帖子 id 挂着，所以公开的帖和你本机的帖都能评。
- 评论立刻可见，但同样只在你自己浏览器里。

### 发布和评论怎么变成"公开"

| 谁操作的 | 怎么让所有人看到 |
| --- | --- |
| 服主 Gun7z | 管理台 → 导出 `content.json`（已包含 `titles`、`posts` 和每条帖的 `comments`）→ 上传覆盖到仓库 |
| 有头衔的成员 | 「发布」页 → 导出我的发布 → `posts.json` → 发给服主 → 服主在「发布管理」导入（同 id 的帖不会覆盖，只补评论）→ 再导出 `content.json` 上传 |

### 五条必须知道的限制

1. **服主密码写在源码里**：`index.html` 中有 `OWNER = { name: 'Gun7z', pwd: 'Gun7z' }`，按 F12 就能看到。看到的人都能以服主身份进管理台。
2. **白名单只挡随手注册**：懂技术的人在浏览器控制台改一下 `localStorage` 就绕过了。它防的是「随手点两下多注册一个号」，不是防有意攻击。
3. **防不住多号的根本原因**：每个访客的账号存在他自己的浏览器里，彼此不通信。同一个名字可以在别人的设备上单独注册一次，白名单只限制了「名字选项」，证明不了「这个人只注册过一次」。
4. **图片是塞进 content.json 的**：上传的图会压成长边 1080 的 JPEG 再转成 base64，每张约 100–400KB。放十几张没问题，但别把它当图库用——文件太大，GitHub 打开和上传都会变慢。
5. **评论同样是本机数据**：你在这台电脑上看到的评论，别人看不到；反过来也是。想全员可见仍要走「服主导出 content.json / 成员导出 posts.json 交给服主合并」这条路。真要做实时评论必须接后端。

### 真要防多号，两条路

| 方案 | 做法 | 代价 |
| --- | --- | --- |
| 接后端账号 | Supabase / Firebase Auth，一个邮箱一个号，服务端管白名单和在线状态 | 免费额度够用，要配密钥、改代码 |
| 关掉注册 | 只留服主登录，成员不注册，看站点就行 | 最省事，零成本 |

要哪一种，跟我说，我来改。

## 六、接上后端（Supabase）＋ 一键发布：从此不用手动传文件

这一节做完之后：成员用**邮箱 + 密码**登录，发帖 / 评论 / 授权头衔 / 改页面正文**直接写进云端**，有人发新内容全站几秒内自动刷新，你不用再导出上传。

### 6.1 开一个 Supabase 项目（免费）

1. 打开 [supabase.com](https://supabase.com) → 用 GitHub 账号登录 → **New project**
2. 名字随便（如 `lyt`），Region 选 `Northeast Asia (Tokyo)` 或 `Southeast Asia (Singapore)`，套餐选 **Free**
3. 等 2 分钟建库完成，进项目 → 右上 **Settings → API**，抄下两个值：
   - `Project URL`：形如 `https://xxxxxxxx.supabase.co`
   - `anon public` key：一长串 `eyJ...`
   - **不要**用 `service_role` key（那是管理员密钥，放前端等于把库送人）

### 6.2 建表（一次复制粘贴）

1. 左侧 **SQL Editor** → **New query**
2. 把项目里 `supabase.sql` 的**全部内容**粘进去 → **Run**
3. 没有报错就说明六张表（`members / whitelist / titles / pages / posts / comments`）、权限规则（RLS）、实时推送都建好了；末尾会预置白名单 `Gun7z`

### 6.3 关掉邮箱验证（不然注册完登不上）

**Authentication → Providers → Email** → 把 **Confirm email** 关掉 → Save。
否则新注册的账号要先去邮箱点确认链接，点之前没有登录态，页面会报"注册成功但没登录"。

### 6.4 填进站里

1. 打开网站 → 用服主账号进**管理台** → 找到「云端设置（Supabase）」
2. 粘贴 `Project URL` 和 `anon public` → 点 **保存云端配置** → 再点 **连通性测试**，看到绿字即通
3. 点下面的 **发布到线上**（见 6.5），把这两个值一起写进 `content.json`，全站就都切到云端模式

切过去之后，登录框自动变成「邮箱 + 密码 + 用户名」，注册时用户名必须在白名单里（服务端也会再查一次，绕不过）。

### 6.5 配一次 GitHub 一键发布（以后改静态页也不用点网页）

让管理台的「发布到线上」直接 commit 到仓库，需要一枚写权限 token：

1. GitHub → 头像 → **Settings → Developer settings → Personal access tokens → Fine-grained tokens** → **Generate new token**
2. Repository access 选 **Only select repositories** → 选你的网站仓库
3. Permissions 只勾 **Contents: Read and write**（其他都不用）
4. 生成后复制 `github_pat_...`（离开页面就看不到了）
5. 管理台「发布到线上」填：`用户名`（如 `gun7z`）、`仓库名`（如 `lytzy`）、`分支`（`main`）、`Token` → 点 **保存** 存好，以后点 **发布到线上** 即可

token 只存在你本机浏览器的 `lyt_gh` 里，不会写进 `content.json`，也不会上传到仓库。换电脑要重新填一次。

| 要改什么 | 怎么做 | 多久生效 |

| 头衔授予 / 撤销 | 管理台「头衔授权」 | 立刻 |
